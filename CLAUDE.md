# CLAUDE.md

## Overview

Pluck (repo: pitch-recognizer) — guitar tuner, chord recognition + ear-training web app. App icon master: `icons/pluck-icon.png` (sizes in `public/` are generated from it). Listens via microphone, detects sung/played
pitch, and offers six tabs: **Tuner** (tunings, A4, reference tones), **Chords** (live recognizer, chord library, identifier), **Scales** (fretboard explorer/identifier with diatonic chords, progressions, circle of fifths), **Trainer** (notes on a staff, interval and chord-quality ear training, chord changes, technique exercises on tab), **Metronome**, **Settings**. Vanilla TypeScript — no
framework. Deps: `vexflow` (notation) only; pitch detection is our own MPM (`ts/core/microphone.ts`, FFT in `ts/core/fft.ts`). Vite build (migrated from
webpack), PWA via `vite-plugin-pwa`, deployed on Vercel. See PRODUCT.md and DESIGN.md for
product tone and design-system context.

## Commands

- `npm run dev` — Vite dev server (opens http://localhost:5173; localhost counts as a secure origin for getUserMedia)
- `npm run build` — `tsc --noEmit` (type-check only, strict mode) then `vite build` → `dist/`
- `npm run preview` — preview the production build

- `npm run check:pitch` — synthetic plucked-string self-check of the detection pipeline (Node 24 runs the TS directly)
- `npm run check:chords` — synthetic strummed-chord self-check of chord recognition
- `npm run check:scales` — scale spelling + identifier self-check
- `npm run check:tunings` — tuning presets, nearest-string and A4 clamp self-check
- `npm run check:metronome` — drives the click engine with a fake audio clock and a jittery timer (spacing, accents, subdivisions, mute, speed trainer, bar-length change, subdivision shrink mid-beat, stalls)
- `npm run check:chord-theory` — chord spelling, identifier, diatonic chords, 19 chord-book voicings in the generator's top 3
- `npm run check:ear` — ear-training questions, playback timing, sung answers, scoring
- `npm run check:chord-library` — chord library helpers (root labels, type groups, keys containing a chord, symbol parsing, marked shape → notes)
- `npm run check:harmony` — keys, progressions, circle of fifths, scales for a chord
- `npm run check:changes` — chord-change drill: stabilizer, change counter (phantom flips), in-time judging, speed-up, records
- `npm run check:tab` — tab exercises (generated, playable, whole bars), note follower, note judging, Tempo / Wait sessions played by a simulated guitarist against a fake metronome, and every exercise but the bends played as plucked strings through the real pipeline (right ≥ 90% on time, a fret off ≤ 20%, ±160 ms late/early); ~80 s
- `npm run check:settings` — corrupt stored settings go through `load()` (localStorage stub)
- `npm run check:note-names` — the four note naming systems (letters, Do Re Mi, French, German H/B), spoken names, device language
- `npm run check:i18n` — every literal `t()` / `plural()` key in `ts/` and the table names views translate (chord/scale types, progressions, intervals, tunings) have Italian, placeholders kept (a translation may add `{A}`…`{G}` note names); helpers; lists entries that look unused
- `npm run replay -- <report.txt|json> <report.webm> [--fps 60]` — replays a field report (Calibration → Diagnostics → Field report): lines the audio up with the log by the recorded clicks, finds the real strums in the sound, runs the app's front end on it (processFrame, the Changes strum detector through `Tab.createHeldGate`, Tab's pick detector), compares the log's judged changes with the strums heard and places the changes by sound as In time does (`by sound, from the click` counts changes within ±200 ms of their click); `LOUDER=`, `LOUDER_MS=`, `BETTER=`, `BETTER_MS=`, `CLICK=louder|off` change the In time rules (defaults = `changes.session.ts`, `off` drops a rule), `A4=` replays the profiles on another reference, `TUNE=1` adds a grid of strum-detector settings, `PROFILES=1` (mean profile per chord), `DUMP=n` (first n strums with shares), `NOISE=1` (strums' and Tab picks' level `AFTER` ms on over the noise floor). Tune timing on field data with it, not on guesses (docs/adr/0009)
- `npm run bench` — dataset benchmark (see bench/README.md); reports the **test** split by default, tune constants with `--split tune` only

- `npm run check` — every `check:*` above in turn, stops at the first failure (shared boilerplate in `scripts/check.ts`)
- `npm run typecheck` — `ts/` plus, via `tsconfig.scripts.json`, `scripts/`, `tests/` and `playwright.config.ts`
- `npm run lint` / `npm run format` — Biome (tabs, single quotes, no semicolons, width 160; disabled rules in docs/adr/0002)
- `npm run test:visual` — builds, serves the production build on port 4179 and compares ~150 Chromium screenshots (375×812, 768×1024, 1280×800 × light/dark, plus 375×812 night and 375×812 Italian light/dark (`phone-light-it`, `phone-dark-it`: an it-IT device), every tab and sub-mode) in `tests/visual/__screenshots__/`, plus a few behaviour checks; the mic is always refused and `Math.random` seeded; tolerance is 20 px per shot (`maxDiffPixels`), so even a small icon change fails. After an intended UI change run `npm run test:visual:update` and review the changed PNGs before committing. Baselines come from Windows; other OSes need their own. First time: `npx playwright install chromium`. **Any refactor must keep this at 0 diffs.** `tests/visual/i18n.spec.ts` (Italian projects only) opens every screen in English and Italian and fails on any text left the same unless the dictionary says it stays (an entry equal to its English).

Design explorations (mockups, not wired to the app) live in `docs/design/` — e.g. `metronome-style-explorations.html`, six restylings of the Metronome page, open it in a browser.

Architecture decisions are recorded in `docs/adr/` (Nygard format); add one for each new structural choice.

## Structure

- Folders: `ts/main.ts` (bootstrap), `ts/core/` (runtime services: microphone, fft, sound, metronome engine, settings, notes), `ts/music/` (pure logic; the Node checks import it with explicit `.ts` extensions — keep those), `ts/ui/` (`view.ts`, fretboard, music-renderer, help), `ts/features/<tab>/*.view.ts` (one folder per tab), `ts/styles/` (tokens, style, fonts), `tests/visual/`, `docs/adr/`.
- `index.html` — app shell (all markup lives here; TS only wires it up). Inline head script resolves theme before first paint.
- Languages and note names (docs/adr/0010): `ts/language.ts` is the first import of `main.ts` and runs before any view module: resolves the `language` setting (`ts/core/locale.ts` `languageFor`: auto = first of `navigator.languages` Pluck speaks, else English) and `noteNames` (`noteSystemFor`: auto = Do Re Mi in Italian, letters otherwise), calls `useLanguage` / `useNoteSystem`, sets `<html lang>`, translates `index.html` (`ts/ui/translate.ts`), marks long tab labels (`.tab__label--long`, IMPOSTAZIONI), and reloads the app when either setting changes. The head script picks the same language and keeps the page hidden (`data-i18n="pending"`, base.css) until then. `ts/core/i18n.ts` (pure, Node-safe, English until set): the English text is the key — `t(key, params)`, `plural(n, one, other, params)` (Intl.PluralRules; `{one, other}` entries), `num(x, digits)` (Intl.NumberFormat), `currentLanguage()`; `context|English` keys where one word means two things (`tuner|Chromatic`, `knob|None`, `chord|Next`). Dictionary `ts/i18n/it.ts`, keyed by the English. `ts/ui/translate.ts` looks up every text node and `aria-label` / `title` / `placeholder` / `alt` / `data-title` / meta description; a block mixing text and inline markup holding text is looked up as its inner HTML; text under `data-i18n="ctx"` as `ctx|text` first. Pure modules call `t()` at call time, never at module level (`settings.ts` evaluates some before the language is set); tables keep English names and views translate them (`t(type.name)`, `Ear.nameOf`). Tab exercises: names / instructions translated in `exercise()`, `{A}`…`{G}` in a translation are note names. `ts/music/note-names.ts`: `NOTE_SYSTEMS`, `formatNote(name, system)` (notes, pitches, chord symbols, slash pairs; keeps `#`/`b` or `♯`/`♭`; German B → H, Bb → B), `spokenNote`, and `noteName()` / `spokenName()` in the system in use. Everything stored, compared or logged stays in letters (ids, records, VexFlow, timing logs). Guide: `help-<tab>-it` templates (Italian), `help.ts` opens the one for `currentLanguage()`.
- `ts/main.ts` — bootstrap: routes six hash tabs (`#tuner` default / `#chords` / `#scales` / `#trainer` / `#metronome` / `#settings`). Only routing + boot: `activate()` stops every app sound (`Sound.stopAll()`, `Sound.stopTone()`), stops the Metronome tab's clicks unless the new tab is Metronome or Settings (the metronome view's `stop()`), resets the old view, scrolls to the top (`history.scrollRestoration = 'manual'`), shows the section, remembers `lastTab` (last tab other than Settings), calls `micNeedChanged()` and `onActivate()`.
- `ts/ui/mic-block.ts` — owns the mic: start/stop/resume, the blocked state, the shared `#mic` block (button, status, moved under the active view's `.readout`; `ui/waveform.ts`, `ui/debug.ts` for `?debug`). Mic auto-starts on load (if the browser suspends the AudioContext until a gesture, status says "Tap to start" and any tap resumes). Views implement `wantsMic()` and call `micNeedChanged()` when it changes; the mic stops where it is false (Metronome, Settings, Chords Library/Identify, Trainer Chords, Intervals unless sung answers are on) and restarts after unless the user had stopped it (`micResume`). Scales uses `micState()` / `setListening(on)` / `onMicChange(fn)`, Changes `focusMicButton()`. The module never imports a view (`initMic(() => activeView)`, `bootMic()` from main.ts). See docs/adr/0006.
- Split feature files: Changes = `changes.view.ts` (DOM) + `changes.session.ts` (DOM-free state machine taking `SessionUi` callbacks and a `MetronomeControl`, covered by `check:changes`) + `changes.recognizer.ts` (recognizer seam + `?debug` `pluckChanges`). Harmony uses `scales/circle.ts` (`createCircle(svg, onChoose)` → `render`) and `scales/progression-player.ts` (`createProgressionPlayer(hooks)` → `play/stop/playing`).
- Shared helpers (use them instead of re-implementing): `ts/ui/dom.ts` — `scoped(root)` → `$`/`$$`, `byId`, `svgEl(tag, attrs)` (attributes in order), `setPressed(buttons, on)`, `bindSegmented(container, attr, onPick)` → `show(value)`, `liveRegion(el, { throttleMs, dedupe })` → `announce(text, force?)`, `onBareKey(roots, keys, handler, allow?)` (document shortcut only while every root is shown, target is body or `allow`ed, no modifiers/repeat; 'Space' by code, others by key), `whenVisible` / `subscribeVisible` (Settings.subscribe skipped while the view is hidden). `ts/core/storage.ts` — `readString/writeString/remove/readJSON/writeJSON`, never throw. `ts/ui/media.ts` — shared `phone` and `reducedMotion` MediaQueryLists. `ts/core/math.ts` — `clamp`. `ts/ui/tempo.ts` — `onPress(button, action, repeat)` (pointer-down, hold to repeat), `bindTempoKeys(buttons, nudge)` (`data-tempo` −10 − + +10, ±1 speeds up when held), `numberField(input, get, set)` → `show(n, force?)`: a typed number on an LCD (`input.lcd-number` + `.lcd__unit` in panel.css; Metronome tempo and trainer target, Changes and progression tempo, Tab tempo). `Sound.strum(midis, { step, at?, ringMs?, stop? })` — stopAll + 1/sqrt(n) gain + stagger. Components in `ts/ui/`: `chordDiagram(rootPc, type, voicing, opts)` → `{ el, render(), destroy() }`; `createReadout(root)` → `idle(text, centre?)` / `show(label, line, cents, locked)` (Tuner, Trainer Notes); `screenLock(active)` → `{ hold(), release() }` (Metronome, Changes); `resultButton` (Scales Identify). `ts/ui/events.ts` holds `OPEN_CHORD_EVENT`; `degreeRole` lives in `ts/music/scales.ts`, `withSilenceReset(tracker, ms)` in `ts/music/chords.ts`. Components created repeatedly own an AbortController that `destroy()` aborts.
- `ts/features/calibration/` — the calibration page `#calibration` (no tab: Settings stays lit, Back returns where you came from; `main.ts` keeps `calibrationFrom`), docs/adr/0009. Two guided steps (Audio delay by tapping, Mic delay by the mic hearing its own clicks; `audioCalibratedAt` / `micCalibratedAt` dates), then Diagnostics: field report (`field-report.ts`, setting `fieldReport`: while on, MediaRecorder on the mic stream of every Changes In time / Tab session + the session's timing log; per report Download / Share (Web Share; audio type without its codecs parameter and the log as .txt: Android Chrome shares neither .json nor .zip and refused `audio/webm;codecs=opus`; a refused share downloads), and with 2+ reports Share all / Download all as one stored .zip via `ts/core/zip.ts`; the last 3 in memory until the app closes), Mic check (live level, noise, strums counted as Changes takes them — through `Tab.createHeldGate` — and only if the sound then is tonal:  `Changes.spectralFlatness` < `MAX_FLATNESS` 0.18: a breath reads ≥ 0.48, a whisper 0.22; chord heard and naming delay), Last session (timeline from `changesTimeline`, log, Copy), Fine-tune by hand. No timing log in the exercises themselves. Ways in: the Calibration section on top of Settings (folding like the others: Audio delay and Mic delay values, "Not set" until done, a Calibrate key) and a muted "Timing calibration" link after the Guide key at the bottom of Trainer → Changes and Tab (`.view-foot`, `data-only="changes tab"`). Mic check runs are field reports too (strums fired and counted). `calibration-state.ts`: `bindCalibrationLinks(root)` (every `[data-action="open-calibration"]`, wired once from main.ts) and `showCalibrationState(root)` (fills `[data-cal-lamp|value|when]` for both steps; Settings and the page).
- Guide: `ts/ui/help.ts` opens one `<dialog id="help">` filled from `<template id="help-<tab>">` in index.html. Entry points stay quiet on purpose: a small dark `.foot-key` "Guide" in each tab's `.view-foot` (bottom left, `order: 99`; the Metronome's two-tap Reset sits before it, Trainer's Timing calibration link after it; colours are the `--foot-*` tokens, Broadcast sets them in its key bezel) and a "Guide" row in Settings → Help.
- `ts/core/microphone.ts` — Web Audio capture + pitch detection loop. `getStats()` also carries `pitch`, the frame's own pitch before smoothing (0 = none), and `getFramePower()` the frame's power spectrum (null when too quiet); Trainer → Tab reads those, not the smoothed reading.
- `?debug` in the URL: live line under the mic button (level, learned noise, clarity, why the frame did not read) and a button recording 20 s of the raw mic stream exactly as the app hears it — replay it with the scripts to tune on field data instead of guessing.
- `ts/music/game.ts` — round logic, scoring, sustain ("hold") detection; best streak in localStorage (`pitch-recognizer:best`).
- `ts/core/settings.ts` — settings store with subscribe/update, persisted to localStorage (`pitch-recognizer:settings`).
- `ts/core/notes.ts` — note/frequency table + helpers (`getClosestNote(f, a4)`, `centsBetween`, `pitchClass`, `frequencyOfMidi(midi, a4)`, `midiOfFrequency(hz, a4)`). Playable pool: E2–C5.
- `ts/music/tuning.ts` — pure: `TUNINGS` (10 presets: standard, drop D, half/whole step down, DADGAD, open G/D/E, …), `tuningStrings`, `nearestString`, `clampA4`.
- `ts/core/metronome.ts` — pure engine with its own AudioContext, no DOM: `configure` / `setTempo` / `start` / `stop` / `onBeat(cb)` / `getState` (reusable by a chord-change trainer). Chris Wilson lookahead: a Blob-worker 25 ms timer (`setInterval` fallback) schedules 120 ms ahead on the audio clock (1.6 s while hidden). Clicks sit at `beatTime + sub * beatDur / subdivision`, so a subdivision change cannot shift the grid and tempo changes land on the next beat; steps > 50 ms late after a stall are skipped, not played in a burst. Beat events fire when the click is heard (audio clock + `outputLatency` + the user's `outputDelayMs`). Synth click / wood / beep at accent, normal, subdivision levels; the speed trainer raises the tempo at bar lines and `stop()` restores the base.
- `ts/music/chords.ts` — learned chord recognition. The 16384-point spectrum (second `AnalyserNode`, `Microphone.getSpectrum()`) is resampled to a log-frequency grid (3 bins/semitone) on the A4 reference and harmonically stacked (sub-harmonics 1/5–1/2, harmonics 1–7); three pitch-equivariant convs give a salience per semitone C2–B6; chroma, bass chroma and pooled features go to an MLP shared by all 12 roots over maj, m, 7, m7, maj7, 9, sus2, sus4 + "no chord". Weights in `ts/music/chord-model.ts` (10.7k params; generated by `scripts/chord-train.py` from `scripts/chord-data.ts` features: tune split + 160 synthetic takes; never edit by hand) are a separate chunk loaded on first use (`loadChordModel()`, `chordModelReady()`); until then every call answers "no chord". `recognizeChord(spectrumDb, binHz, a4 = 440)` reads one frame; `createChordTracker()` → `{ track(spectrumDb, binHz, timeMs, a4), reset() }` adds online HMM forward filtering (time-based switch rate, no-chord and per-type offsets); `trackChord` / `resetChordTracking` wrap a default tracker used by the Chords view and the bench. The view resets it after 300 ms of continuous silence and shows a label once it persists 150 ms. ~0.6 ms/frame. Recipe and per-dataset results in `bench/README.md` (2026-10-19; test numbers are optimistic: IDMT slow/fast and GuitarSet players share pieces and guitars — the GuitarSet row is the honest one).
- `ts/music/scales.ts` — pure scale data (`SCALE_TYPES`: degree formulas like `1 2 b3 4 5 b6 b7`, semitones and letter spelling derive from them; table order = commonness, the identifier tiebreak), fretboard constants (standard tuning, frets 0–22) and `identifyScales` (all roots × types containing the marked pitch classes, ranked by fewest extra notes, then root = lowest marked note).
- `ts/core/sound.ts` — Karplus–Strong plucked-string synth with its own AudioContext: `play(midi, delay, volume?, ringMs?)`, `stopAll()`, `NOTE_MS`, `playTone` / `stopTone` (exact-pitch reference tone). `isRinging()` makes Scales, Chords Listen, Trainer Notes and ear training ignore the mic while the speaker plays.
- `ts/ui/fretboard.ts` — the shared SVG neck. `createFretboard(svg, board | null, { tuning?, onTap?, fill?, autoRender? })` → `{ render(spec), light(heard, playing?), revealBox(), destroy() }`. Spec: dots (string 0 = high E, fret, `role` root / tone / note / marked / optional, label, detail for aria, `marked`, `dimmed`, `finger`), optional position `box`, `barres`, open/muted `strings` markers, `toggles` (Identify), `label`, `window: { from, frets = 4, vertical = true }` for a compact chord diagram (nut or "Nfr"). Reads orientation, fret size, board theme and `leftHanded` (mirrors x only, text never transformed; a horizontal left-handed board keeps its gap to the right edge). Interactive only with `onTap`, otherwise the svg is `role="img"` named by `spec.label`. `autoRender` redraws on settings changes (call `destroy()`). Keep the Scales markup byte-identical when touching it.
- `ts/music/chord-theory.ts` (pure) — `CHORD_TYPES` as degree formulas (same shape as `ScaleType`, 9/11/13 an octave up), `spellChord`, `identifyChords(pcs, bass?)` (root must be played; ≤ 1 extra and ≤ 1 missing required tone, omittable tones missing at half cost; exact → fewest missing + extra → root = bass → commonness), `chordsOfScale(rootPc, scaleType)` (triads + sevenths, numerals relative to major; `[]` unless 7 notes in stacked thirds).
- `ts/music/chord-shapes.ts` (pure) — `chordShapes(rootPc, type, { tuning, maxFret, limit, inversions })` (cached, results read-only; 4-fret span + open strings, ≤ 4 fingers, barre only with > 4 fretted notes, open-string shapes fit frets 1–4, scored for playability), `Voicing` (`frets`, `fingers`, `barre`, `base`, `high`, `from` = diagram start), `voicingSpec(voicing, rootPc, type, options?)` → ready `NeckSpec`, `shapeString` (x32010).
- `ts/music/ear.ts` — pure ear-training logic for the Trainer's Intervals / Chords exercises: `INTERVALS` (m2…P8), `QUALITIES` (formula + barre voicing, roots E2–E3, top ≤ E5), `makeQuestion` (no immediate repeat; up/down/harmonic/mixed), `playback` (melodic gap, harmonic, 30 ms strum, per-note gain), `intervalOfAnswer` (sung answer → interval, octaves folded, reference and non-enabled intervals = no answer), per-exercise score/streak/stats, best streak in `pitch-recognizer:best:intervals` / `:chords`. `ts/features/trainer/ear.view.ts` wires it: Play/Replay (Space; `Sound.stopAll()` first), Next (Enter; auto-advance 700 ms after a right answer, cancelled by `reset()` or exercise/tab change), wrong answer reveals the right one and every button then plays its own version, sung answers for intervals (held `HOLD_MS`, each pluck masks the mic for `Sound.NOTE_MS` via `Sound.play`'s `ringMs`), weakest-first session bars. `ts/features/trainer/trainer.view.ts` switches Notes / Intervals / Chords (`trainerExercise`, validated on load with `earIntervals` / `earChords`), toggles `[data-only]` and filters trainer settings sections by `data-exercise`. Views may implement `wantsMic()`; `index.ts` turns the mic off where it returns false (Metronome, Chords exercise) and back on after (`micResume`).
- `ts/features/chords/chord-library.view.ts` — the Chords tab's Listen / Library / Identify switch (`chordsMode`, validated in `load()` like `chordLabels` / `chordPlay`). Only Listen uses the mic: `createChordsView(root, onMicNeed)` passes `onMicNeed` to `createChordModes`, `wantsMic()` = `modes.listening()`, `onReading` does nothing elsewhere. Library: root chips + grouped type select → symbol, spelled notes/degrees, "In keys" chips (major / natural-minor keys via `chordsOfScale`), up to 8 voicing diagrams (`chordShapes` + `voicingSpec`, drawn lazily via IntersectionObserver, `destroy()`ed on change; tap = `Sound.stopAll()` then strum 30 ms/string or arpeggio per `chordPlay`, 1/sqrt(n) gain; labels per `chordLabels`). One settings subscription (no `autoRender`) redraws drawn diagrams and the Identify neck only when labels, left-handed or board theme change. Identify: full neck, one note per string (tap again clears, unmarked = muted), `identifyChords` with the lowest pitch as bass, results open in the Library, best match announced via `aria-live`. `openChord(symbol)` is called by the Listen readout (a button, disabled while idle) and by a `pluck:open-chord` window event (`detail.symbol`), before or after the `#chords` hash change. Pure helpers in `ts/music/chord-library.ts`.
- `ts/music/harmony.ts` (pure) — `familyOf`, `chordSource` (pentatonics / blues → parent major or natural minor), `keyOf` / `keyName` (modes map to their parent major: "D Dorian · parent C major, no sharps or flats"), `PROGRESSIONS` spelled on the key's letters by `resolveProgression`, `progressionsFor` (major/minor scales and pentatonics; 12-bar blues also for blues, minor pentatonic, Mixolydian), `CIRCLE` (12 keys, signatures, F#/Gb), `scalesForChord`.
- `ts/features/scales/harmony.view.ts` — the Chords · Progressions · Circle section under the Scales neck (Explore) and the "chord fits" row in Identify. The Scales view owns the neck: it calls `harmony.render(state)`, lights `harmony.chord()`, ignores the mic while `harmony.playing()`. Strums: cached easiest voicing, 1/sqrt(n) gain, `ringMs = Sound.NOTE_MS`, `Sound.stopAll()` on chord tap / Strum / progression start-stop; leaving Progressions stops playback. Chords pane: Triads ⟷ 7ths slide switch (`chordView`) with a printed line explaining them. Progressions pane: the key + Loop slide switch, Tempo as in Trainer → Tab (`.changes-stepper` ▼ LCD ▲, ±5 BPM), then one step sequencer per progression: a small ▶/■ transport key at the head of the row (down and lit while it plays), one small key per bar (`.progression__step` > `.key.progression__chord` with the lamp in the cap, the numeral printed under); a step strums its chord alone (`previewBar`: stops playback, lamp lit and neck lit for `Sound.NOTE_MS`). The circle pane has room above and below the dial. Bars timed with setTimeout from a fixed start, both strums of a bar on the audio clock; the live region announces only start / stop / end. "Open in Chords" fires `pluck:open-chord`. Settings `chordView`, `progressionBpm` (60–140), `progressionLoop`, validated in `load()`.
- `ts/music/changes.ts` (pure) — chord-change drill: `createStabilizer` (a chord counts once named for 70 ms, short gaps bridged, onsets backdated; a direct flip is fresh only with a strum within `ATTACK_LEAD_MS` = 800 before it and after the previous run began), `createChangeCounter` (next chord in sequence order only; a change needs a strum, a gap or another chord in between and is ignored within 400 ms of the last one, so a held chord the recognizer flips C↔Am never counts), `judge` (hit within `hitWindow` = max(120 ms, min(200 ms, slot/4)) of the downbeat, early/late within half a slot, else miss; `offset` = the deciding onset's ms off the downbeat), `afterMark` (+5 BPM after 2 clean passes, applied on the next chord's first beat), records per pair and length in `pitch-recognizer:changes:<pair>` (never saved with 0 changes).
- `ts/features/trainer/changes.view.ts` — Trainer → Changes: One-minute (count-in, countdown, best + sparkline) and In time (shared `ts/core/metronome.ts`; the Metronome view configures the engine only while its tab is visible and restores its own tempo on entry; the LCD is a grid with Hearing on top, Now ▶ Next as large, a segment per beat of the chord lit by `SessionUi.beat`; under it a timing meter, ±500 ms, needle on the last change's offset from `SessionUi.marked(marks, offsets, hitMs)`, on-time zone = `hitWindow`, dots for the 8 before, Miss lamp + tally). A hidden page ends a session. The only recognizer seam is `heardChord(now)`: its own `createChordTracker()` with the tuner's A4, reset after 300 ms of silence and by `resetHeard()` on Start / mic stop; In time hears changes by sound alone (`changes.session.ts`, docs/adr/0009): each strum (`Changes.createStrumDetector`: newest-samples energy ×6 over the last 60 ms, ×1.3 over the frame before, 120 ms refractory, nothing for 500 ms after the first frame, no noise gate; `strummed()` in changes.recognizer.ts) waits 380 ms, then its pitch-class profile 40–200 ms on (`Tab.chromaOf(getFramePower)`, dropped when `Changes.spectralFlatness` ≥ `MAX_FLATNESS` 0.18: breath, blowing, whispers) picks one of the drill's chords (`Changes.drillChord`, largest `chordShare`, null on a tie); it is a change when that chord is not the one ringing, unless a strum 3× louder (peak RMS over 80 ms) follows within 300 ms (the lifted fingers' open strings), dated strum − 15 ms. A strum counts once it rings (`Tab.createHeldGate`: 80 ms on the level still ≥ 2× the mic's learned noise floor; PC fans at −58 dB fired the detector 14 times in 30 s of silence, never holding 1.9×; field strums and Tab notes 2.6× and up; Tab's picks go through it too, the Mic delay calibration does not). Re-strums and clicks sound like the chord ringing, so they never count. A change yields to a strum 3× louder within 300 ms that is not where the mic hears a click (`heardAt + CLICK_HEARD_MS` 22 ± 15: an unplugged electric's clicks were louder than its strums), or to one within `BETTER_MS` (700) reading the same chord with `BETTER` (0.1) more share (open strings on beat 4 read as G a little) and not on a click unless it is one too (a faint change strum lost to the next click, a beat late); decided `DECIDE_MS` = 900 ms on. Clicks are never masked: a change strummed right on the click is a strum. Profiles use the Tuner's A4 (a guitar tuned off it smears every note over two pitch classes; `npm run replay` prints its tuning). On six field reports: 200 of 213 changes within ±200 ms of the click. The recognizer only feeds the Hearing line and One-minute. Every session keeps a timing log (`timing-probe.ts`: beats with `heardAt` vs `getOutputTimestamp`, strums, the changes placed and why the other strums were not (`passed`: no drill chord, the chord ringing, a louder / clearer strum after), judged offsets, picks vs notes) for the calibration page. The recognizer's names go through `Changes.sequenceChord` first: the drill's chord sharing the most notes (≥ 2, no tie), so Em7 counts as G and A7 as C (a field report: 13 of 28 changes found by name, 26 so). The model loads when the exercise opens. `?debug`: `pluckChanges.hear('G' | null, strum?)` / `.off()` feed fake chords.

## Architecture

Audio pipeline: `getUserMedia` (echoCancellation/autoGainControl/noiseSuppression all **off** —
voice processing distorts steady tones) → two 70 Hz high-pass biquads (cut mains hum under the
low E) + 1.4 kHz low-pass (guitar band) → `AnalyserNode` (fftSize 4096, ~7.6 periods of E2) → per-frame `requestAnimationFrame`
loop → `processFrame` (pure per-frame logic, exported for `npm run check:pitch`). There: RMS
envelope **onset detection** restarts tracking on each pluck and blanks the attack; **MPM** with
the autocorrelation computed from the power spectrum after **spectral subtraction** of the room
noise (×3, averaged from frames near the floor with no periodicity at guitar lags — removes hum,
fans, whines) and key maxima searched only at guitar lags (60–1400 Hz); accepted only if RMS clears an **adaptive noise gate** (≥ 0.0003 ≈ −70 dBFS, so an unplugged electric works, and ≥ 3× a
noise floor learned only from unpitched frames — a fixed 0.015 gate cut the thin high E string;
with **hysteresis**: a new note needs 2× the floor and clarity ≥ 0.85, a note already tracked keeps
reading down to 1.2× and clarity ≥ 0.7 while its pitch stays put, so an unplugged electric's
sustain is followed instead of freezing the needle) and 60–1400 Hz; **octave-up check**
(if the NSDF peak at 2τ beats the one at τ by > 0.05 the note is an octave lower; 0.02 pushed
acoustic notes an octave down); **octave lock**
folds readings ~1 octave from the tracked pitch back unless they persist 300 ms; 7-sample
**median window**; **One Euro filter**. Short dropouts (≤ 200 ms) repeat the last reading so the
tuner does not flicker and the trainer hold is not reset by one bad frame. Constants are
justified in comments (McLeod's MPM thesis). Views receive `PitchReading | null` (null = silence)
through the active view's `onReading`.

Trainer: `game.evaluate()` requires the target held on-pitch for 350 ms (HOLD_MS) to win a
round. `matchAnyOctave` compares pitch classes instead of exact notes. Settings changes
revalidate the current target against the active pool.

Tuner: needle position = cents clamped to ±50; readout locks green within the `tolerance` setting.
Smoothing lives entirely in `microphone.ts`, not the tuner view.

## Style guide (the look, in words)

Read this before drawing any screen, theme or component; DESIGN.md and the tokens are how it is built.

- **What it is**: tactile hardware skeuomorphism, kept quiet. Each screen is the front panel of a real device from the late 70s–80s: a studio rack unit, a Japanese cassette deck or hi-fi, lab test gear, a Braun / Dieter Rams calculator, a drum machine. Not the glossy skeuomorphism of 2010 phone apps (leather, glass blobs, heavy reflections), not flat UI either: physical objects, drawn with restraint.
- **Depth, in two directions only**: controls come *out* of the panel, windows go *in*. Out = keys, knobs, the plate, toggles: lit top edge (a thin chamfer of light), shaded cheeks, a darker front edge, a short soft shadow underneath. In = LCD windows, wells, slots, fader tracks, holes: a black bezel, an inner shadow under the top edge, a hairline of light on the lower lip. A latched key sinks (3 px) and darkens a shade; nothing grows or bounces. Every component must read as either standing out or sunk in.
- **One light**: from above (a touch from the left). Highlights are thin lines on top edges; shadows fall below. Glow only where the real thing emits light: lamps, LEDs, LCD ink, a lit legend.
- **Restraint, not kitsch**: gradients only to describe a material (the curve of a knob, the brushing of a plate, the slope of a key), 2–3 stops, low contrast; never a rainbow, a glossy highlight blob or bevel on bevel. Textures (grain, brushing, mesh) sit at a few percent opacity: visible only when you look for them, never under running text, flat colour is the default (the user dislikes strong textures, especially on the lower panel). Colour comes from materials (cream, graphite, aluminium, enamel, lacquer); saturated colour is kept for lamps, LCD ink and one hot key per view (Start).
- **Shape**: rectangles with small radii (keys 2–4 px, lamps 1 px, windows 2–5 px). No pill keys, no big rounding (the user rejected them). Hairline rules, 1.5 px outlines, real-scale details (a 13 × 5 px lamp, a printed tick scale).
- **Type is printing**: labels are silk-screened on the panel (condensed, uppercase, tracked: Barlow Semi Condensed), printed above or below the control as on a faceplate; values live on glass (display face on LCDs); running text is plain (Geist). No decorative type outside the display faces a user picks.
- **The two base themes** (everything else varies these):
  - *Classic light*: a beige 80s deck. Brushed aluminium plate (fine horizontal brushing, `#d9d9d5`→`#c9c9c4`, dark silk), cream painted panel `#e7e1d3` with a faint dark grain, cream keys `#ede7d8` with a white top chamfer and a tan front edge `#b5ad9b`, grey stepper keys, small black keys for − +, one orange Start `#e8742c`, a grey-green reflective LCD `#c7c9bb` behind a black bezel, small red rectangular lamps, paper strips for charts.
  - *Classic dark*: the same unit in a studio at night. Graphite plate `#3d3d3f`→`#2f2f31` with light silk, anthracite panel `#2a2825` with a faint light grain, dark keys `#3d3a36` with a soft lit chamfer and a near-black front, the same orange Start, an amber backlit LCD `#f5a742` with dark segments, amber lamps.
- **Feel: every interaction is tactile.** A control must feel pressed, not just look pressed; touching the app should be satisfying, like operating good hardware. Each interactive component gets all three:
  - *Movement*: light and quick, barely noticed: a key sinks as the finger lands (≈ 60–90 ms, ease-out) and springs back on release; a knob turns with a hint of weight and settles on its detent; a switch snaps across; a lamp or legend lights with a short fade (≈ 80–120 ms); a fader cap follows the finger exactly. No bounce, no overshoot, no long transitions, nothing that delays the result; with reduced motion, state changes stay instant.
  - *Sound*: a tiny, short click for every movement, matched to the mechanism (`ts/ui/feedback.ts`: `key` momentary press, `latch` a latching key going down or up, `rocker` a switch flipping, `detent` each click of a knob, stepper or dropdown). Synthesized, a few milliseconds, quiet, never musical; settings `uiSounds` / `uiVolume`; each click masks the mic for a moment (`Sound.mask`) so listening views do not hear it. A new kind of control picks the closest kind or adds one there, never an audio file.
  - *Touch*: a short haptic tick with the click where the device can (`haptics`: `navigator.vibrate` on Android, the hidden-switch Taptic tick on iPhone).
  Wire new controls into feedback.ts (it delegates by element; knobs and dropdowns call `detent()` themselves). A control without feedback is unfinished.
- **Before shipping a component, check**: does it click, tick and move when touched? Would it exist on a real device? Does it stand out (light on top, shadow below) or sit in (inner shadow, bezel)? Is its texture visible only up close? Does it work in every theme and LCD colour with tokens only? Is it still calm next to the readout, the hero of each screen?

## Procedures (every change)

- **Text the user reads or hears is translated.** Write it in English, then:
  - in TS: `t('English sentence')` from `ts/core/i18n` (`'../core/i18n.ts'` with the extension in `ts/music/` and anything the Node checks import); values as placeholders (`t('Find {note}', { note })`), counts with `plural(n, '{n} change', '{n} changes')`, decimals with `num(x, 1)`, dates/times with `currentLanguage()` as the locale. Never build a sentence by concatenating English fragments, never pluralise with `n === 1 ? 'x' : 'xs'`.
  - in `index.html`: plain English text and `aria-label` / `title` / `placeholder`; `ts/ui/translate.ts` translates it at boot. A word that means two things gets a context: `data-i18n="ctx"` on the element (HTML) or `t('ctx|Word')` (TS).
  - table names (chord / scale types, progressions, goals, levels…) stay English in `ts/music/`; the view shows `t(name)`; add the table to `scripts/i18n-check.ts` if it is new.
  - call `t()` when the text is shown, never at module level (modules imported by `settings.ts` run before the language is set).
  - add the Italian to `ts/i18n/it.ts` (key = the exact English; an entry equal to the English when the word stays the same, e.g. `Loop`, `Tap`). Short: keys and small LCDs are upper-cased and narrow; check the Italian at 375 px.
  - Guide: change both `<template id="help-<tab>">` and `help-<tab>-it`.
  - run `npm run check:i18n`; `npm run test:visual` runs `tests/visual/i18n.spec.ts` (Italian projects), which fails on any English left on an Italian screen.
  - not translated: brand and plate model names (PLUCK, TUNER · TU-100), units (BPM, Hz, ms), chord suffixes, interval ids, `?debug`, timing logs and field reports (they are for replay).
- **Notes and chord symbols are shown through `noteName()`** (`ts/music/note-names.ts`), spoken through `spokenName()`; what is stored, compared, logged or passed to VexFlow stays in letters. A sentence that names notes takes `{A}`…`{G}` placeholders in the translation (see `exercise()` in `ts/music/tab.ts`).
- **Every component works in every theme and LCD colour.** No colour outside `tokens.css`: use the material tokens (`--key*`, `--lcd-*`, `--panel*`, `--ink*`…) or the generic roles, SVG through classes / `currentColor` / `var(--token)`. If a new component needs a material no token covers, add the token to every theme × mode block in `tokens.css` (and to `regia.css` where Broadcast draws it differently), not to one theme. LCD parts use `--lcd-*` only, so every display colour applies. ## Fragile areas

- **VexFlow rendering**: `music-renderer.ts` rebuilds the Factory from scratch each round
  (reuse stacks notes) and wraps the whole draw in try/catch — on failure it clears the staff
  and logs, keeping the round playable via the text note name. Low notes are written +1 octave
  under an 8va treble clef; unparseable spellings throw before drawing.
- **The rAF detection loop must never die**: `microphone.ts` wraps frame processing in
  try/finally so a throwing frame still reschedules; `index.ts` additionally try/catches each
  `view.onReading` call. Preserve both guards when touching the pipeline.
